# hyper / h2 / hyper-util / reqwest / http: complaint survey + HTTP spec baseline

Research date: 2026-11-14. Sources: GitHub issue search (unauthenticated API), issue pages, httpwg.org/specs, datatracker httpbis, RFC Editor errata.
Status = state at research time. "Root cause" = what the thread says; *(unconfirmed)* where maintainers did not agree.

**Already known, not re-researched:** h2 single big mutex (h2#531, draft PR h2#917, 15-40% gains but lost-wakeup/deadlock issues); one H2 conn per host in the legacy pool (hyper#2641, #3623); `max_concurrent_streams` exposure (hyper#4026); composable pools (hyper#3948/#3849); H2 slower than H1 (hyper#3071); per-connection dispatch channel memory (hyper#4057).

Repos: `hyper` = hyperium/hyper, `h2` = hyperium/h2, `hu` = hyperium/hyper-util, `rq` = seanmonstar/reqwest, `http` = hyperium/http.

---

## 1. Prioritized complaint table

Impact: **T** = throughput, **L** = latency/tail, **A** = allocations/memory, **C** = correctness/liveness (stalls, hangs), **E** = ergonomics.
Priority: **P0** = design must address from day 1; **P1** = important; **P2** = nice to have / API polish.

### Cross-cutting design takeaways (from the above)
1. **Write coalescing everywhere** (#1, #2, #12, #13): one connection-level write buffer plus writev, frame batching, HEADERS+DATA+trailers in one syscall. NODELAY on.
2. **Read/write independence and fairness** (#3, #4): budgeted frame processing, never block reads on writes.
3. **Flow control as a memory budget, not an app-polling side effect** (#5, #6, #19).
4. **Lock-free or sharded pool with O(1) cancellation and explicit state machine** (#7, #8, #22).
5. **Typed retry safety** (#9): GOAWAY last-stream-id and REFUSED_STREAM mean "not processed".
6. **Cancellation is first-class** (#10, #11): drop → immediate RST/close; per-phase deadlines inside the protocol.
7. **Allocation budget tested in CI** (#16, #17, #18, #25).
8. **Observability zero-cost by default** (#15, #27).

### 2.4 Implementation-relevant MUSTs (hyper/h2 history noted)

**HTTP/2 (RFC 9113)**
- **§8.2.2 connection-specific fields**: never send `Connection`, `Keep-Alive`, `Proxy-Connection`, `Transfer-Encoding`, or `Upgrade`. `TE` only with value `trailers`. Receiving them = malformed. *hyper PR #4194 (open): strip TE when any value is not `trailers`.*
- **§8.2.1 field validity**: names lowercase, no uppercase ASCII, no `:` except pseudo-headers. Values have no NUL/CR/LF and no leading/trailing SP/HTAB. Receivers MUST treat violations as malformed (stream PROTOCOL_ERROR). *h2#342 (pseudo-header logging), h2#984 (pseudo-headers in trailers silently discarded).*
- **§8.3**: pseudo-headers precede regular fields, no duplicates, not in trailers. `:authority` SHOULD be used instead of `Host`; if both, they must match. Errata 9175 (OPTIONS with a query). hyper#2208 (can't omit `:authority`).
- **§8.1.1 content-length**: mismatch with the DATA sum = malformed. HEAD/304 must not get a body (*hyper PR #4237, zero body size for HEAD*).
- **§6.5.3 SETTINGS**: ACK every SETTINGS promptly. Local settings apply only after the peer ACKs. Initial window changes (§6.9.2) adjust all open streams and can make windows negative. *h2#704 (settings not applied correctly), h2#299, h2#976 (stall after ACK shrinks the window).*
- **SETTINGS_MAX_CONCURRENT_STREAMS**: unlimited until the peer's first SETTINGS arrives (the client should assume a conservative value, ~100). The peer can lower it at any time. Exceeding it → REFUSED_STREAM. Reserved/pushed streams count (*h2#968*). Default client: set ENABLE_PUSH=0.
- **§6.9 flow control**: window ≤ 2^31−1 → FLOW_CONTROL_ERROR (stream or connection). WINDOW_UPDATE increment 0 → PROTOCOL_ERROR (stream error on a stream, connection error on stream 0) (*h2#892*). Malformed control frames → FRAME_SIZE_ERROR/FLOW_CONTROL_ERROR (*h2#992, #900*). DATA received after GOAWAY or a reset still counts against the connection window (*h2#895*).
- **§4.2 / §6.5.2 SETTINGS_MAX_FRAME_SIZE**: 2^14 (default) to 2^24−1. Frames over the peer's limit → FRAME_SIZE_ERROR. Must track changes (*h2#197 open*). Performance: frame size vs TLS record size (*h2#797*).
- **§6.10 CONTINUATION**: must follow contiguously on the same stream. Cap the total header-block size (SETTINGS_MAX_HEADER_LIST_SIZE is advisory, so enforce a local hard limit too). CONTINUATION flood (VU#421644, Apr 2024, fixed in h2 0.4.4).
- **§6.8 GOAWAY**: stream ID must be 0 (*h2#951*). Streams above last-stream-id are unprocessed and safe to retry. Send GOAWAY(NO_ERROR) with 2^31−1 first for graceful close, then the real last ID. Errors on GOAWAY must keep their code (*hyper#4268*).
- **§8.7 retry**: REFUSED_STREAM and streams above the GOAWAY ID are guaranteed unprocessed, so retry automatically even for non-idempotent methods.
- **§5.4.2 / §5.1**: RST_STREAM on idle stream = PROTOCOL_ERROR (*h2#875*). Ignore frames on recently closed streams for a while (*h2#983*). An END_STREAM received before a connection error must be preserved (*h2#977*).
- **Rapid-reset class**: CVE-2023-44487 (Rapid Reset), CVE-2025-8671 (MadeYouReset: server-induced resets via invalid frames), small/empty DATA floods (GHSA-q83h-524g-xf6h, h2#948). Mostly server-side, but a client must also bound peer-induced resets, PING and SETTINGS floods, and empty frames.
- **§9.1 connection management**: client SHOULD NOT open more than one connection per origin. A new one is fine when MAX_CONCURRENT_STREAMS is exhausted (the hyper#2641 debate). Reuse across origins requires a cert covering the origin plus DNS match or ORIGIN frame (RFC 8336).
- **§9.2 TLS**: TLS ≥1.2, SNI MUST, the TLS 1.2 cipher blocklist (Appendix A) → INADEQUATE_SECURITY, no renegotiation, no compression. ALPN `h2`. The 0-RTT/early-data rules are in RFC 8470.
- **HPACK (RFC 7541)**: dynamic table size update MUST be at the start of the first header block after the table-size SETTINGS ACK. Use never-indexed for `authorization` and short `cookie` values. Bound decoder memory. Option to disable the dynamic table (*h2#780*).

**HTTP/1.1 (RFC 9112)**
- §6.3 message length: both `Transfer-Encoding` and `Content-Length` → TE wins, and the client should close the connection after the response (smuggling). `chunked` must be final. Invalid CL → unrecoverable error. hyper#2427 open on CL/TE problems.
- §5.1: no whitespace between field name and colon (reject). obs-fold in responses: replace with SP or reject. Bare CR: reject. Limits: hyper#3523 (`max_headers`), hyper#3832.
- §9.3 persistence: read the full response before reuse. Retry only idempotent requests automatically (RFC 9110 §9.2.2), plus QUERY (RFC 10008). Pipelining is SHOULD NOT for non-idempotent methods.
- §9.6 tear-down / §9.8 TLS close_notify: treat a missing close_notify with a known length as OK. Treat a truncated chunked or close-delimited body as incomplete (hyper#3759, SSE `IncompleteMessage`).
- RFC 9931: no optimistic data after Upgrade/CONNECT before a 2xx/101.

**Semantics (RFC 9110)**
- §15.2: client MUST parse any number of 1xx before the final response (100, 103, 104 for resumable upload), even if unsolicited. 101 only with Upgrade (H1).
- §10.1.1 Expect: 100-continue. Client may send the body after a timeout without 100. A final status before the body → stop sending (H1: close or finish. H2: RST_STREAM NO_ERROR after END_STREAM on the response).
- §6.5 trailers: don't merge into headers unless allowed. Send only if `TE: trailers` (H1) or always OK on H2.
- §7.2 Host/authority: Host must equal the target authority.
- §9.2.2 idempotent methods: GET, HEAD, OPTIONS, TRACE, PUT, DELETE (+ QUERY).

### 2.5 Recommended baseline for the new client
- **Must**: 9110, 9112, 9113 (incl. errata 9175), 7541, 9218 (send NO_RFC7540_PRIORITIES; optional Priority header), 9651, 8441, 9931 compliance, 10008 QUERY idempotency, full 1xx handling, 100-continue, trailers, GOAWAY/REFUSED_STREAM typed retry, RFC 8305 Happy Eyeballs v2 (+ RFC 9460 HTTPS RR optional).
- **Next**: 9114/9204 + 9220 + 9297 (HTTP/3 via quinn or s2n-quic); Alt-Svc 7838 / HTTPS RR discovery; ORIGIN 8336/9412 for coalescing.
- **Optional modules**: 9111 + 9875 + no-vary-search (cache), 9842 (dictionary compression), 9530/9421, resumable uploads (draft-15), cookies 6265bis.
